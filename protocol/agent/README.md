# Прокси для автономных агентов

Агент говорит с прокси как с обычным OpenAI-совместимым сервером, а
прокси превращает каждый запрос в задание реестра и **платит кошельком
самого агента в AXM**. Ответ агент получает только после того, как
независимый узел-проверяющий подтвердил его, пересчитав вероятности.

```
агент ──OpenAI API──► прокси ──submit_job + uaxm──► реестр ◄── узлы с залогом
  ▲                    │  ▲                                     │
  └── ответ + вердикт ─┘  └──── текст запроса (подпись, шифр) ──┘
```

Посредника с деньгами нет: ни счёта у шлюза, ни баланса в базе. Монеты
лежат на адресе агента и уходят прямо в контракт. Возвраты контракт
шлёт обратно на адрес агента: за снятое невзятое задание, за закрытое
без вердикта и цену за ответ, признанный негодным.

Один прокси обслуживает одного агента с одним ключом. Если агентов
десять, нужно десять прокси, и у каждого свой кошелёк и свой потолок
трат.

## Что нужно

| Что | Зачем |
|---|---|
| кошелёк агента `axm1…` с AXM | из него оплачиваются задания и газ |
| тот же ключ в связке `axmd` (`KEY`) | подпись сделок (`axmd` v2.2.1, как в образе узла) |
| тот же ключ файлом, 64 hex (`SIGN_KEY`) | подпись запросов к узлам: связку с ответом узел отдаёт только заказчику |
| адрес, видимый снаружи (`PROMPT_URI`) | по нему узлы забирают текст запроса |

Прокси сам проверяет, что `SIGN_KEY` и `KEY` дают один адрес, иначе не
запускается.

## Запуск

```sh
axmd keys import-hex agent <64 hex> --keyring-backend test   # один раз
echo -n '<64 hex>' > agent.key && chmod 600 agent.key

CONTRACT=axm1fe5dsxm3vcnwjkvlgjk9mkvqnl6ggpay3y3r94hls7g3hz4s68tqcp547r \
KEY=agent SIGN_KEY=./agent.key \
PROMPT_URI=http://ВНЕШНИЙ-АДРЕС:8090 \
MAX_SPEND_DAY=1000000 \
python3 -u protocol/agent/proxy.py
```

Если в вашей версии `axmd` нет команды `keys import-hex`, ключ
восстанавливается из сид-фразы командой `axmd keys add agent --recover`.
Тип монеты для Axiome 546.

**Признак, что прокси поднялся:** в выводе есть строка
`агент axm1…, реестр …, модель …; запрос стоит …`, а `GET /healthz`
отдаёт `"ok": true`.

| Переменная | По умолчанию | Что это |
|---|---|---|
| `CONTRACT` | — | реестр. Его расчёт обязан быть `{"native":"uaxm"}`, иначе прокси отказывает |
| `KEY`, `SIGN_KEY` | — | ключ агента: имя в связке `axmd` и файл |
| `PROMPT_URI`, `PROMPT_PORT` | —, `8090` | откуда узлы берут текст запроса (снаружи) и какой порт для этого слушается |
| `API_HOST`, `API_PORT` | `127.0.0.1`, `8088` | API для агента |
| `API_TOKEN` | пусто | `Authorization: Bearer …`. Обязателен, если API открыт не на localhost |
| `PRICE` | `10000` | цена задания узлу в uaxm; доля проверяющих (сейчас 4,85%) добавляется сверху по данным цепочки |
| `MAX_SPEND_DAY` | `1000000` | потолок трат в сутки (UTC) в uaxm, без газа. Возвраты не вычитаются |
| `MODE` | `settled` | `settled`: ответ только после вердикта. `answer`: ответ сразу, с `verified: false` |
| `OPEN_TIMEOUT` | `900` | через сколько секунд снимать невзятое задание (деньги вернутся) |
| `WAIT_TIMEOUT` | `1800` | сколько держать HTTP-запрос; дальше 504 с номером задания |
| `MAX_CHARS` | `8000` | предел длины запроса |
| `CHAT_TEMPLATE` | `auto` | шаблон диалога по модели реестра |
| `REST`, `NODE`, `CHAIN_ID`, `GAS_PRICES`, `AXMD_HOME`, `KEYRING_BACKEND`, `DB`, `PROMPTS_DIR` | Axiome | цепочка и файлы |

## Как агент вызывает прокси

Любой клиент OpenAI подойдёт:

```python
from openai import OpenAI
llm = OpenAI(base_url="http://127.0.0.1:8088/v1", api_key="API_TOKEN или что угодно")
r = llm.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    messages=[{"role": "user", "content": "Столица Франции?"}])
print(r.choices[0].message.content)
print(r.model_extra["verification"])   # job_id, verdict, executor, txhash, paid
```

| Путь | Что делает |
|---|---|
| `POST /v1/chat/completions` | поставить задание и дождаться ответа. Роли `system`, `user`, `assistant` |
| `POST /v1/completions` | то же для голого текста, без шаблона |
| `POST /v1/jobs` | поставить задание (`prompt` или `messages`) и сразу получить `job_id` |
| `GET /v1/jobs/<номер>` | что с заданием; `answer` заполнен, когда ответ подтверждён (или сдан, но вердикта ещё нет — тогда `verified: false`) |
| `GET /v1/models` | модель, прибитая в реестре |
| `GET /healthz` | адрес агента, цена запроса, потрачено за сутки (без токена) |

В тело можно добавить `"verification": "answer"`, чтобы для этого
запроса не ждать вердикта.

Коды ошибок:

| Код | Что это | Деньги |
|---|---|---|
| 400 | неверный запрос | не тронуты |
| 402 | потолок трат на сутки | не тронуты |
| 502 | сделка не прошла, или проверяющие признали ответ негодным | в первом случае не тронуты, во втором цена вернулась |
| 503 | цепочка не отвечает, или у реестра расчёт не в uaxm | не тронуты |
| 504 | задание закрыто без вердикта (деньги вернулись), или ещё в работе (номер в `error.job_id`, ответ забирается позже) | — |

## Чего здесь нет и почему

- **`max_tokens`, `temperature` и прочие параметры порождения
  игнорируются.** Они прибиты на узлах: на других параметрах проверку не
  пересчитать, ведь порог 0,0360 измерен для этих.
- **`stream` не поддерживается.** Ответ отдаётся только после сверки с
  хэшами в цепочке, а сверить половину ответа нельзя.
- **Подсчёта токенов нет:** `usage` нулевой, плата фиксирована за
  задание (`PRICE`).
- **Подпись без `axmd` пока не сделана.** Сделки подписывает `axmd`, как
  у узла и у бота. Если агенту нужна поставка без внешних бинарников,
  это следующий шаг: подпись и отправка `MsgExecuteContract` на чистом
  Python.

## Проверка

```sh
python3 protocol/agent/test_proxy.py
```

Тест поднимает настоящий HTTP-сервер прокси на подставной цепочке и
проверяет:

- оплату монетой uaxm и выкладку текста до сделки;
- шаблон диалога;
- что негодный и непроверенный ответы не отдаются;
- режим `answer`;
- снятие невзятого задания;
- потолок трат;
- токен API;
- допуск узлов к тексту по подписи.
