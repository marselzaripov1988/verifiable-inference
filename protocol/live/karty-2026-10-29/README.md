него проверено было всё по отдельности: правило — на сохранённых
векторах, петля и заказчик — на местной цепочке с подставным vLLM, две

Прогон стоил **$1,90** аренды и около **0,8 AXM** газа. Машины погашены.

## Что сработало само, без человека

* **Адреса доставки взяты из цепочки.** Петли запущены **без** `--peers`:
  ни один узел не знал адресов соседей. Связку они забрали по `endpoint`
  из записи исполнителя — `связка получена из http://81.27.69.180:29317/2.json`.
* **Запрос — по `prompt_uri` из задания**, который назвал заказчик.
* **Задания найдены запросом списка:** `заданий с 1: 1 (список, граница 2)`.
* **Срок отобрал брошенное задание.** node1 взял задание 1 и не смог
  достать запрос; по истечении 600 с его отобрали, и задание подобрал
  node3. В записи node1 остался счётчик `abandoned: 1` — и ни бана, ни
  изъятия залога: брошенное задание не доказывает подлога.
* **Гонки за `finalize` и `claim_job`** проиграны многократно и ни одну
  петлю не уронили: `опоздали: … code=5` и дальше по циклу.
* **Залог вернулся целиком** всем трём, статус стал `pending`, контракт
  опустел.

## Чего прогон стоил по граблям

1. **Узел не может забрать файл со своего же публичного адреса.** Запрос
   лежал на node1 и отдавался по `http://81.27.69.180:29396`; сам node1
   получал оттуда `urlopen error timed out` — NAT на арендованной машине
   не разворачивает пакет обратно. Из-за этого он и бросил задание 1.
   Лечится локальным зеркалом: во втором круге у каждого узла был
   `--prompts /root/prompts`, и исполнитель прочитал запрос с диска —
   `запрос получен из /root/prompts/bd49d6d0….txt, сошёлся с цепочкой`.
   Доставка недоверенная, поэтому читать с диска так же законно, как по
   http: решает хэш.
2. **`axmd` не стартует без `libwasmvm.x86_64.so`** — её надо кладть
   рядом и объявлять `LD_LIBRARY_PATH`.
3. **`pkill -f "[l]oop.py"` убивает собственную оболочку по ssh**, если в
   той же команде есть `loop.py`. Рабочий шаблон — `pkill -f "loop[.]py"`.
4. **`axm-lcd.trickle.pro` отдаёт `panic` с одного из узлов за
   балансировщиком.** Заказчик получил отказ, через три секунды тот же
   запрос прошёл. Петля такие отказы считает недоступностью цепочки и
   просто ждёт — ровно для этого различение и сделано.

## Чего прогон НЕ проверил

* **веса залога.** 0,1 AXM — не 30 400, и изъятие здесь не больно;
* **подлога.** Все три узла честные, вердикт `guilty` вживую не
  вынесен — он проверен тестами контракта и прогонами на местной цепочке;
* **долгой работы.** Полтора часа, два задания. Сутки под нагрузкой не
  проверялись;
* **четвёртой карты.** Класс по-прежнему «модель карты»: про RTX 4080 или
  L40S прогон не говорит ничего.
