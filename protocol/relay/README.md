# Посредник для текстов запросов

Агенту больше не нужен открытый порт. С посредником прокси агента
(`protocol/agent`) работает из любой сети: из дома за роутером, из
офиса, из облака без белого адреса.

## Зачем

В задании в цепочке лежит только хэш вопроса. Текст исполнитель
забирает сам по адресу `prompt_uri`, который назвал заказчик. Без
посредника этот адрес — сам прокси агента, и до него должны дозвониться
узлы снаружи.

С посредником всё иначе:

```
агент ──PUT текст (подпись агента)──► посредник ◄──GET (подпись узла)── узел
  │                                    https://…/relay       текст шифром для узла
  └──submit_job, prompt_uri = посредник──► реестр
```

- **Агент только отправляет**, исходящими запросами. Так работает любая
  сеть.
- **Узлы не меняются.** Для них посредник — обычный `prompt_uri`, и
  забирают они текст тем же подписанным запросом, что у бота.
- **Контракт не меняется.**

## Кому отдаётся текст

Правило то же, что у бота и у прокси (`sign.Access.may_read`):

- **исполнителю задания**, пока задание взято или ответ сдан;
- **действующим узлам реестра** после сдачи ответа: проверяющих заранее
  не знает никто.

Ответ шифруется ключом того, кто спросил. Подписи нет — ничего не
отдаётся.

Задание посредник ищет сам: среди последних `SCAN` заданий каждого
реестра — то, у которого этот хэш и заказчик — тот же адрес, что
подписал выкладку. Чужой текст под своим заданием раздать нельзя.

## Чего посредник не делает

- **Не хранит деньги и ключи.**
- **Не держит тексты дольше нужного.** Текст закрытого задания стирается
  при ближайшей уборке (раз в 5 минут). Текст, под который так и не
  появилось задание, стирается через `UNCLAIMED_TTL`. Любой текст
  стирается через `MAX_AGE`.
- **Не прячет текст от хозяина сервера.** Тот может его прочесть, как и
  хозяин сервера бота. Шифруется только дорога до узла.

## Защита от засорения

- Текст обязан совпасть с хэшем в имени.
- Размер текста не больше `MAX_BYTES`.
- У одного адреса не больше `MAX_PENDING` текстов, под которые ещё нет
  задания.

## Настройки

| Переменная | По умолчанию | Что это |
|---|---|---|
| `REGISTRIES` | четыре реестра из УЗЕЛ.md | через запятую. Где искать задания |
| `REST` | `https://axm-lcd.trickle.pro` | LCD Axiome |
| `HOST`, `PORT` | `127.0.0.1`, `8097` | где слушать. Наружу — только через HTTPS |
| `DIR`, `DB` | `./relay-prompts`, `./relay.sqlite` | тексты и чей текст |
| `MAX_BYTES` | `65536` | предел текста |
| `MAX_PENDING` | `20` | текстов без задания на один адрес |
| `UNCLAIMED_TTL` | `3600` | через сколько секунд стереть текст без задания |
| `MAX_AGE` | `259200` | предел жизни любого текста (3 суток) |
| `SCAN` | `200` | сколько последних заданий реестра просматривать |

## Развёртывание

Удобнее всего на том же сервере и домене, что кабинет узла
(`protocol/cabinet/РАЗВЁРТЫВАНИЕ.md`), путём `/relay`. Тогда адрес
посредника — `https://<домен кабинета>/relay`.

**1. Служба.** Код уже лежит в `/opt/verifiable-inference`, если там
стоит кабинет. Обновите его: `cd /opt/verifiable-inference && sudo git pull`.

```sh
sudo tee /etc/systemd/system/vi-relay.service >/dev/null <<'EOF'
[Unit]
Description=Посредник текстов запросов (verifiable inference)
After=network-online.target

[Service]
WorkingDirectory=/var/lib/vi-relay
Environment=DIR=/var/lib/vi-relay/prompts DB=/var/lib/vi-relay/relay.sqlite
Environment=HOST=127.0.0.1 PORT=8097
ExecStart=/usr/bin/python3 -u /opt/verifiable-inference/protocol/relay/relay.py
Restart=always
RestartSec=5
DynamicUser=yes
StateDirectory=vi-relay

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now vi-relay
```

**Признак:** `journalctl -u vi-relay -n 5` показывает строку
`посредник: http://127.0.0.1:8097/`, а `curl -s localhost:8097/healthz`
отвечает `{"ok": true, …}`.

**2. HTTPS.** Добавьте в блок домена кабинета в `/etc/caddy/Caddyfile`
строку `handle /relay/*` **перед** общим `reverse_proxy`:

```
cabinet.example.org {
    handle /relay/* {
        reverse_proxy 127.0.0.1:8097
    }
    reverse_proxy 127.0.0.1:8095
}
```

```sh
sudo systemctl reload caddy
```

Приставку `/relay` **не срезать** (`handle`, а не `handle_path`). Узел
подписывает полный путь, и со срезанной приставкой подпись не сойдётся.

**Признак:** `curl -s https://cabinet.example.org/relay/healthz`
снаружи отвечает `{"ok": true, …}`.

**3. Сообщить адрес.** Адрес посредника для агентов —
`https://cabinet.example.org/relay`.

## Проверка

```sh
python3 protocol/relay/test_relay.py
```

29 проверок на подставной цепочке и через настоящий HTTP:

- **выкладка:** подпись, сверка с хэшем, предел размера, предел
  засорения;
- **раздача:** исполнитель получает, после сдачи ответа получает
  проверяющий, посторонний и неподписанный — нет;
- **текст забирается тем же кодом, что на узлах**
  (`delivery.fetch_verified`), и сходится с хэшем;
- **чужой текст под своим заданием не раздаётся**;
- **тот же вопрос новым заданием находится заново**;
- **путь с приставкой `/relay`** работает;
- **уборка:** закрытое, невостребованное и просроченное стирается.

25 ноября 2026 поиск задания проверен на живой цепочке: четыре реестра
просмотрены за 3,8 с, настоящее задание найдено, а для чужого заказчика
не найдено ничего.
