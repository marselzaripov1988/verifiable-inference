# Канонический кеш ядер класса

Этот архив — часть закрепляемой связки, наравне с моделью, рантаймом и
точностью. Без него узлы одного класса считают **по-разному в последнем
бите**, и сверка хэшей невозможна. С ним — считают побитово одинаково.

Устройство целиком: [`protocol/ВЕРДИКТ.md`](../../ВЕРДИКТ.md).
Замеры: [`results/bitwise-pairs/`](../../../research/inference-determinism/results/bitwise-pairs/)
и [`results/zero-tolerance/`](../../../research/inference-determinism/results/zero-tolerance/).

## Что это и зачем

vLLM автотюнингует ядра Triton **замером скорости на машине**, и выбор
зависит от шума. Один и тот же вектор получается разным, когда выбран
разный блок свёртки (`R0_BLOCK` 4096 против 2048): на Ampere это уводит
вектор на 20 053 миллионных, на Ada — на 6, но побитовое равенство
ломается в обоих случаях.

Из четырёх RTX 3090 на четырёх машинах три совпали побитово, а четвёртая
не совпала ни с одной — и дело не в драйвере: у выпавшей был 580.82.09,
то же семейство, что у совпавшей 580.126.09. Кеш совпавшей карты,
перенесённый на выпавшую, дал 300 побитовых совпадений из 300.

| Класс | Значение |
|---|---|
| модель | `Qwen/Qwen2.5-7B-Instruct` |
| рантайм | `vllm-0.31.0` (образ `vllm/vllm-openai:v0.31.0`) |
| точность | `bfloat16` |
| архитектура | `sm_89` — RTX 4090 и прочая Ada |
| кеш | `kernel-cache.tar.gz`, 2 473 326 байт, 424 файла |
| sha256 | `3753554454f2c9b850c6ec0912a58e39ee08028012f3de1e9649e62d67cc131a` |

**Для Ampere нужен свой кеш.** Архив собран под конкретную архитектуру и
на другую не переносится; это не недоделка, а свойство скомпилированного
кода.

## Как поставить

Кеш ставится **до первого запуска сервера**. Иначе vLLM соберёт свой и
узел окажется вне класса.

```sh
sha256sum -c SHA256SUMS            # обязательно: сверить, что скачали то
rm -rf ~/.cache/vllm
mkdir -p ~/.cache && tar xzf kernel-cache.tar.gz -C ~/.cache
```

Запускать строго с теми флагами, при которых кеш собран:

```sh
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --dtype bfloat16 --max-model-len 4096 \
  --gpu-memory-utilization 0.92 \
  --no-enable-prefix-caching --seed 0 \
  --no-enable-flashinfer-autotune \
  --compilation-config '{"inductor_compile_config": {
      "enable_auto_functionalized_v2": false,
      "combo_kernels": false,
      "benchmark_combo_kernel": false}}'
```

Признак, что кеш принят: в журнале запуска **нет** строк
`Compiling a graph`. Если они есть, кеш не подошёл и ядра собраны заново
— узел вне класса.

## Чем проверить, что вышло правильно

Пройти пробу: оценить 34 текста из
[`probe/probe-v2.json`](../probe/probe-v2.json) и сравнить с эталоном.
**Допуск нулевой** — расхождение обязано быть ровно 0 на каждом тексте.

Замерено на этом кеше: честный узел класса (другая машина, другой
драйвер) даёт 0 на всех 34 текстах пробы и на 300 текстах корпуса;
неверный режим `--enforce-eager` не совпал ни на одном (худшее 28 025),
подлог FP8 — ни на одном (худшее 118 136).

## Почему хэш сверяется у скачанного архива, а не у своего

Архив упакован воспроизводимо:

```sh
tar --sort=name --mtime='UTC 1970-01-01' --owner=0 --group=0 \
    --numeric-owner -cf kernel-cache.tar vllm
gzip -n -9 -c kernel-cache.tar > kernel-cache.tar.gz
```

Две независимых упаковки одного кеша дают один sha256 — проверено. Но
кеш, собранный **на другой машине**, даст другие байты даже при
тождественном поведении: у двух карт, дающих одинаковые векторы,
содержимое файлов различается (пути, встроенные хэши), а различаются и
`time_taken_ms` в записях автотюнинга. Поэтому:

* хэш подтверждает, что скачан **именно этот** архив;
* доказать хэшем, что собранный самостоятельно кеш равнозначен, **нельзя**
  — и не нужно: пользоваться надо раздаваемым.

Сводка выбранных конфигураций (`*.best_config` без `time_taken_ms`) для
подписи **не годится** и это замерено: две карты, совпавшие побитово на
всех 334 текстах, имеют разные сводки — различались конфигурацией
поэлементного ядра, где нет свёртки и порядок операций ни на что не
влияет. Сводка остаётся средством разбирательства:
[`fingerprint.sh`](../../../research/inference-determinism/fingerprint.sh)
показывает, какое ядро развело две карты.

## Когда пересобирать

При смене **любой** части связки: модели, версии vLLM, точности,
архитектуры, перечисленных флагов. Новый кеш — новый sha256 в настройках
контракта и новая версия эталона пробы, которая обнуляет все выданные
пробы.

Собрать: на чистой карте нужной архитектуры снести `~/.cache/vllm`,
поднять сервер с теми же флагами, дождаться компиляции, упаковать
командой выше. Эталон пробы снимается тем же прогоном.
