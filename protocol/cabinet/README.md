# Кабинет узла — мини-приложение Telegram для «Кубика»

Владелец видеокарты открывает кабинет в Telegram и видит свои узлы:

- статус в каждом реестре;
- залог;
- шесть шагов готовности;
- сколько заработано как исполнителем и как проверяющим;
- балансы AXM и BARTR.

Там же он подключает новый узел: выбирает карту, записывается в
реестр, вносит залог и получает команду запуска образа.

**Ключей кабинет не видит и не хранит.** Каждое действие — это готовая
строка `axiomesign://` для Axiome Wallet (Axiome Connect: вставить
строку, подтвердить), а рядом та же сделка командой `axmd`. Подписывает
владелец, в своём кошельке. Формат строки тот же, что у оплаты в боте.

**Всё показанное прочитано из цепочки:** запись узла, задания,
проверки. Своей базы с деньгами у кабинета нет. Заработанное считается
так же, как выплачивает контракт: исполнителю цена задания,
проверяющим `fee_total` поровну, пойманному ничего. Выплаты приходят
на адрес узла прямо из контракта, кабинет их только показывает.

## Что внутри

| Экран | Что там |
|---|---|
| **Мои узлы** | список адресов со статусом «работает / не готов / забанен» и заработком |
| **Узел** | балансы; по каждому реестру заработок и счётчики, шесть шагов готовности, действия (внести и забрать залог, сменить адрес, команда запуска, запись) |
| **Подключить** | шесть шагов: карта → кошелёк → запись → залог → запуск образа (и права рабочему ключу) → проверка |

Шесть шагов готовности повторяют то, что контракт проверяет при каждом
взятии задания:

1. записан в реестр;
2. залог не меньше минимума;
3. проба на эталоне сдана;
4. адрес доставки объявлен;
5. адрес доставки отвечает;
6. узел не забанен.

Поля записи (модель, рантайм, класс, кеш ядер) и минимум залога берутся
из цепочки, а не из кода. Если реестр сменит модель, кабинет сам выдаст
новую сделку.

**Пошаговое развёртывание на сервере и подключение к боту:
[РАЗВЁРТЫВАНИЕ.md](РАЗВЁРТЫВАНИЕ.md).**

## Запуск

```sh
TG_TOKEN=<токен бота> \
BOT_DB=/путь/к/bot.sqlite \
python3 -u protocol/cabinet/server.py
```

| Переменная | По умолчанию | Что это |
|---|---|---|
| `TG_TOKEN` | — | токен бота, из которого открывается кабинет. Им проверяется подпись `initData`: без неё любой выдал бы себя за чужой id |
| `BOT_DB` | пусто | база `bot.py`. Добавленный узел становится подпиской бота, и бот пишет владельцу о смене статуса, залога, обвинении и молчащем адресе. Бот следит за своим реестром (`CONTRACT` бота) |
| `REGISTRIES` | четыре реестра из УЗЕЛ.md | через запятую |
| `REST` | `https://axm-lcd.trickle.pro` | LCD Axiome |
| `HOST`, `PORT` | `127.0.0.1`, `8095` | где слушать. Наружу — только через HTTPS-прокси |
| `DB` | `./cabinet.sqlite` | чьи узлы: единственное, что кабинет помнит |
| `REFRESH` | `60` | раз в сколько секунд перечитывать задания реестров |
| `DEV` | `0` | `1` — пускать без `initData` (заголовок `X-Dev-User`). Только для проверки на своей машине |

**Признак:** в выводе по строке `реестр axm1…: RTX 4090` на каждый
реестр, а `GET /` отдаёт страницу.

### HTTPS и Telegram

Telegram открывает мини-приложения только по `https://`. Самое простое
— Caddy перед кабинетом, сертификат он получит сам:

```
cabinet.example.org {
    reverse_proxy 127.0.0.1:8095
}
```

Дальше в @BotFather:

1. `/mybots` → бот → **Bot Settings → Menu Button** → URL
   `https://cabinet.example.org/`, название «Кабинет узла».
2. Если кабинет должен открываться ссылкой из «Кубика»:
   **Bot Settings → Configure Mini App → Enable**, тот же URL. Ссылка
   вида `https://t.me/<бот>/<имя>` откроет кабинет внутри Telegram.

Кабинет должен открываться **тем же ботом**, чей токен в `TG_TOKEN`:
подпись `initData` делается токеном бота, из которого открыт кабинет.

## Проверка

```sh
python3 protocol/cabinet/test_cabinet.py
```

44 проверки на подставной цепочке и через настоящий HTTP:

- подпись и срок `initData`;
- опечатки в адресах;
- точный пересчёт сумм;
- сделки — те же, что в УЗЕЛ.md;
- заработок — как его выплачивает контракт;
- шаги готовности;
- подписка бота.

23 ноября кабинет прогнан и на живой цепочке, в режиме `DEV`. Все
четыре реестра прочитаны. Два узла боевого реестра 4090 показаны с
залогом 1 000 BARTR, заработком 0,220185 AXM и балансами. Адреса
доставки отмечены как не отвечающие: узлы работают в 19:00–21:00 МСК, а
проверка была вне этого окна. Строка записи в реестр собрана с моделью
из цепочки (`huihui-ai/Huihui-Qwen3-8B-abliterated-v2`), а не с той, что
указана в УЗЕЛ.md.

## Чего нет

- **Права рабочему ключу (authz) — только командой `axmd`.** Axiome
  Connect принимает лишь исполнение контракта, а это другая сделка.
- **Владение адресом не проверяется.** Добавить в «мои узлы» можно
  любой адрес: всё показанное и так открыто в цепочке. Подписать сделку
  за чужой адрес кабинет не даёт — подписывает кошелёк.
- **Заработок до перезапуска считается заново.** Задания перечитываются
  из цепочки при старте; на тысячах заданий это минута.
