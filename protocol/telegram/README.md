# Telegram-бот реестра

Один бот для двух сторон.

**Для тех, кто спрашивает.** Человек пишет вопрос — бот ставит задание в
реестр, узел считает ответ, два других узла его проверяют, и только после
вердикта «подтверждён» ответ приходит в чат. Обычно 2–5 минут. Платит
кошелёк бота, человеку кошелёк не нужен.

**Для владельцев узлов.** `/node axm1…` показывает запись узла из цепочки
и включает подписку: бот пишет, когда меняется статус, залог, адрес
доставки, число выполненных и брошенных заданий, когда приходит
обвинение, обнуляется проба и когда адрес доставки перестаёт отвечать.

## Что видит человек

```
Что такое блокчейн?
  Задание 12: ⏳ ждёт исполнителя
  Задание 12: ⚙️ узел считает ответ
  Задание 12: 🔍 ответ готов, идёт проверка: 1 из 2
✅ Ответ подтверждён двумя независимыми узлами (задание 12, исполнитель axm1…)

Блокчейн — это …
```

Первые три строки — одно сообщение, оно меняется на месте. Если
проверяющие признали ответ негодным или проверки не собрались в срок,
ответ **не показывается**: бот не выдаёт непроверенное за проверенное.
Если задание 15 минут никто не берёт, бот снимает его, деньги
возвращаются на кошелёк, а вопрос — в дневной лимит.

| Команда | Что делает |
|---|---|
| текст или `/ask <вопрос>` | задать вопрос |
| `/job <номер>` | что с заданием |
| `/limits` | сколько вопросов осталось сегодня |
| `/hours` | часы работы сети (`HOURS`) и сколько до открытия |
| `/gpu` | как подключить свою видеокарту: образ по digest, реестр бота, `docker run` |
| `/registry` | модель, цена, залог, сколько проверяющих |
| `/node <адрес>` | запись узла и подписка |
| `/unnode <адрес>`, `/nodes` | отписаться, список подписок |
| `/balance` | кошелёк бота (только для `ADMINS`) |

## Как он устроен

Все интерфейсы — цепочка, раздача вопроса, связки узлов, Telegram —
описаны в [API.md](API.md): по нему бота можно написать заново.

- **Ответ не берётся на слово.** Бот забирает связку у исполнителя по
  адресу из цепочки и сверяет её с обоими хэшами задания — тем же кодом,
  что `client.py collect` (`protocol/daemon`). Бот курьер, а не источник
  доверия.
- **Текст вопроса бот раздаёт сам.** Узлы берут его по `PROMPT_URI`, а
  бот слушает `PROMPT_PORT` и отдаёт только `<хэш>.txt` из
  `PROMPTS_DIR`: ни списка каталога, ни других файлов. Текст
  выкладывается до сделки.
- **Вопрос живёт, пока задание в работе.** Хэш вопроса лежит в цепочке
  открыто, поэтому бот отдаёт только `<хэш>.txt` незакрытых заданий, а
  после вердикта или снятия стирает и текст, и сохранённый ответ. При
  запуске он стирает всё, что не нужно заданиям в работе.
- **Вопрос читают только участники задания.** Хэш лежит в цепочке
  открыто, поэтому запрос обязан нести подпись ключом узла
  (`protocol/daemon/sign.py`). Вопрос получает исполнитель взятого
  задания, а когда ответ сдан, ещё и любой действующий узел реестра:
  проверяющих заранее не знает никто. Без подписи бот отвечает 401,
  постороннему 403. Связку узлы отдают так же, только заказчику и
  проверяющим, поэтому бот подписывает свои запросы ключом кошелька
  (`SIGN_KEY`).
- **По проводу идёт шифр.** Ответ на подписанный запрос — и вопрос у
  бота, и связка у узла — шифруется ключом того, кто спросил (ECIES на
  secp256k1, `sign.seal`). Ни тот, кто видит трафик, ни тот, кто
  повторил перехваченный запрос, текста не прочтёт. HTTPS для этого не
  нужен; видно только, кто к кому обращался и за каким хэшем.
- **Сделки по одной.** У кошелька один номер последовательности, поэтому
  вопросы, пришедшие разом, отправляются в цепочку по очереди.
- **Лимит.** `DAILY_LIMIT` вопросов на человека в сутки (UTC), не длиннее
  `MAX_CHARS`. Без лимита кошелёк опустошит первый, кто напишет скрипт.
- **Хранилище** — один файл SQLite (`DB`): лимиты, задания в работе,
  подписки. После перезапуска бот продолжает следить за начатыми
  заданиями.

## Запуск на VPS

Подойдёт самый маленький сервер: 1 ядро, 1 ГБ памяти, Ubuntu или Debian.
Видеокарта не нужна — считают узлы.

### 1. Бот в Telegram

Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → имя → получите
токен вида `123456:ABC…`. Это пароль бота: в репозиторий не кладите.

### 2. Программы

```bash
apt-get update && apt-get install -y python3 git ca-certificates
git clone https://github.com/marselzaripov1988/verifiable-inference /opt/vi
```

`axmd` 2.2.1 и `libwasmvm` 1.5.0 положите так:

```bash
install -m 755 axmd /usr/local/bin/axmd
cp libwasmvm.x86_64.so /usr/lib/ && ldconfig
axmd version
```

### 3. Кошелёк бота

```bash
axmd keys add bot --keyring-backend test --home /opt/vi-bot/axmd
```

Запишите сид-фразу. Положите на адрес AXM: один вопрос стоит
`цена + доля проверяющих` (на тестовом реестре 0,010485 AXM) и около
0,0005 AXM газа, то есть **1 AXM ≈ 90 вопросов**. Держите на кошельке
немного: ключ лежит на сервере без пароля, и украденный сервер — это
украденный остаток.

### 4. Порт для узлов

Узлы должны достучаться до бота за текстом вопроса:

```bash
ufw allow 8080/tcp
```

`PROMPT_URI` — внешний адрес сервера, например `http://203.0.113.5:8080`.

### 5. Настройки

`/opt/vi-bot/env`:

```sh
TG_TOKEN=123456:ABC…
CONTRACT=axm1fe5dsxm3vcnwjkvlgjk9mkvqnl6ggpay3y3r94hls7g3hz4s68tqcp547r
KEY=bot
AXMD_HOME=/opt/vi-bot/axmd
PROMPT_URI=http://203.0.113.5:8080
PROMPTS_DIR=/opt/vi-bot/prompts
DB=/opt/vi-bot/bot.sqlite
ADMINS=123456789
DAILY_LIMIT=3
```

| Переменная | По умолчанию | Что это |
|---|---|---|
| `TG_TOKEN` | — | токен от BotFather |
| `CONTRACT` | — | реестр. Выше — тестовый для 4090; боевые в [../УЗЕЛ.md](../УЗЕЛ.md) |
| `KEY` | — | имя ключа в связке `axmd` |
| `PROMPT_URI` | — | внешний адрес раздачи вопросов |
| `AXMD_HOME` | связка по умолчанию | где лежит ключ |
| `PRICE` | `10000` | цена задания узлу, uaxm; доля проверяющих сверху |
| `DAILY_LIMIT` | `3` | вопросов на человека в сутки |
| `MAX_CHARS` | `2000` | предел длины вопроса |
| `EXPLORER` | `https://axiomechain.org` | обозреватель для ссылок на сделки задания: они приходят с вердиктом и в `/job` |
| `CHAT_TEMPLATE` | `qwen` | в какую обёртку класть вопрос: узел продолжает текст, и без шаблона диалога модель дописывает к вопросу статью вместо ответа. `none` — голый текст |
| `OPEN_TIMEOUT` | `900` | через сколько секунд снять невзятое задание |
| `ADMINS` | пусто | id чатов без лимита и с `/balance` |
| `ALLOWED` | пусто | если задан — бот отвечает только этим id |
| `HOURS` | пусто | часы работы по Москве, например `19-21`. Вне их вопрос не ставится (кроме `ADMINS`): узлы выключены расписанием `protocol/raspisanie`, и задание никто бы не взял |
| `PROMPT_PORT` | `8080` | порт раздачи |
| `SIGN_KEY` | — | файл с ключом кошелька бота (64 hex) для подписи запросов связок. Без него ответы с узлов нового образа не забрать. Бот при запуске сверяет, что ключ даёт адрес кошелька |
| `ALLOW_UNSIGNED` | `0` | `1` — отдавать вопрос и без подписи. Только для узлов старого образа: тогда вопрос открытого задания может скачать любой |
| `REST`, `NODE`, `CHAIN_ID`, `GAS_PRICES` | Axiome | цепочка |

Свой id чата пришлёт [@userinfobot](https://t.me/userinfobot).

### 6. Служба

`/etc/systemd/system/vi-bot.service`:

```ini
[Unit]
Description=verifiable-inference telegram bot
After=network-online.target

[Service]
EnvironmentFile=/opt/vi-bot/env
WorkingDirectory=/opt/vi-bot
ExecStart=/usr/bin/python3 /opt/vi/protocol/telegram/bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now vi-bot
journalctl -u vi-bot -f
```

В журнале должно быть `кошелёк axm1…, реестр axm1…, модель …` и
`запросы раздаются на :8080`. Напишите боту `/registry`, потом вопрос.

## Чего бот не делает

- **Не гарантирует ответ.** Если в реестре нет трёх работающих узлов,
  задание никто не возьмёт или не проверит: бот снимет его через
  `OPEN_TIMEOUT`, а взятое и не проверенное закроется сроком без оплаты.
- **Не принимает оплату от людей.** Платит кошелёк бота; лимит — вся
  защита от расхода.
- **Не видит петлю узла изнутри.** О том, что узел упал, бот узнаёт по
  молчанию адреса доставки (две проверки подряд, раз в минуту) и по
  брошенным заданиям в цепочке.

## Проверка

```bash
python3 protocol/telegram/test_bot.py
```

Подставные цепочка и Telegram: текст до сделки, точная
сумма, ответ только с вердиктом, лимит и его возврат, снятие невзятого,
тревоги владельцу узла, раздача только нужных файлов.
